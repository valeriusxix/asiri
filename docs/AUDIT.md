# Asiri: independent pre-submission audit

Audited on 2026-10-27, 14:30 to 15:45, at commit `92f6855` (clean tree), against `Agent.md`. No source file was changed. The probe scripts and screenshots live outside the repo, in `%TEMP%\asiri-audit\` (`probe/`, `pw/`, `shots/`).

## 1. Verdict

**It is safe to submit after about two hours of fixes, but not as it stands.** No BLOCKER was found: build, tests, the mock demo and the claim money logic all hold up, including under concurrency. Four HIGH issues could embarrass you in front of judges or put a deployed fund at risk. Fix them first, in this order: H1 (the public example `SESSION_SECRET` forges admin sessions, even in production), H2 (mock mode shows a fake QR code and a fake viewing key as if they were real), H3 (an unauthenticated `mock-donate` lets anyone on the network deface the public totals), and H4 (the demo script exposes the default admin login on venue Wi-Fi).

**Status, 2026-10-28:** all seven items marked "fix before submission: yes" (H1–H4, M1–M3) are fixed on branch `audit-fixes`, one commit each, every one with a test that fails on the old code. `npm run typecheck && npm test && npm run build` is green after every commit: 121 API tests plus 9 new web render tests. Items marked "no" or "optional" are untouched. See section 2a.

- **Double claims are impossible.** The one-statement `UPDATE … WHERE status='active' AND claim_token_hash=? AND claim_token_expires_at>?` held against 20 concurrent redeems. Two separate unlocks invalidate the first token.
- **PIN lockout holds under concurrency.** 40 parallel wrong PINs produced exactly 4 × 401 and 36 × 423, with `pin_attempts = 5` and the payout locked. Admin unlock resets it, and a second unlock gives 409.
- **Send-failure rollback is clean.** Three failed sends (ZcashError, `funds_pending`, generic Error) each returned the payout to `active` with balances unchanged. A retry with the same token succeeded, with exactly one ledger row and correct transparency totals.
- **Balance math is right**, including D-002. Demo cash-outs stay earmarked (`settledOffchainZat`), and cancel and expiry release reservations. 10 concurrent ₦500k creates on ₦1.6M produced 3 × 201 and 7 × 409.
- **Privacy plumbing is solid.** The secret travels only in POST bodies. Request logs hold method, path, status and duration only. The database holds only hashes. Bank details are discarded. No secrets in git history.
- **The recipient path is clear at 360 px**: big amount, plain copy, Demo badges on the cash-out, and no overflow. `check-copy.mjs` guards the strings.
